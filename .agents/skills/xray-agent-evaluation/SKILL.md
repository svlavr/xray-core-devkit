# Evaluate delivered outcomes

Read `docs/PROJECT_SCOPE.md` and
`docs/WORKFLOW.md#invention-criticism-and-experiments`. Main supplies the original
task, permitted candidates and evaluation boundary. Assign `mu_agent_evaluator`
an independent evidence question; it does not acquire implementation or
publication authority. An algorithm comparison can use the same method when a
real executable outcome evaluator exists.

Bind evidence to exact task/input, root/base/candidate, consumer, model/profile,
harness/tool/environment and run identities. Distinguish configured roles from
observed effective model/runtime identity, and independent runs from several
lenses in one session. Keep original proposals, criticism, revisions, artifacts,
failed attempts and results reviewable alongside synthesis. Never substitute a
convenient historical or wrong-root receipt for the actual candidate.

Before comparing candidates, verify the acceptance evaluator with known-invalid
and deceptively green examples. Cover complete consumer behavior, missed
defects, false findings, incorrect closure, scope revision and operational
failures; use time/token cost only after outcome quality. Include ambiguous
requirements, a justified direct win and a useful unfamiliar alternative when
relevant. Compare matched inputs and held-out variants; repeat where stochastic
or measurement variance could change the conclusion. Do not claim general
improvement from a single synthetic probe or propagate a noisy winner globally.

Use `xray-decision-experiment` for actual candidate execution by an authorized
worker. Preserve the distinction between scheduled, generated, evaluated and
accepted results. A failed selector, unavailable observation, unchanged seed or
exit-zero task runner is not a newly delivered improvement. Human/model judgment
may explain evidence or unresolved tradeoffs; polished prose, keywords, votes,
novelty and an LLM score cannot replace executable correctness evidence.

Main adjudicates findings against the full justified objective, sends repair to
the authorized writer and returns decisive feedback to creators, critics and
the affected acceptance check. Evidence may revise a requirement with an
explicit reason; silently omitted behavior is incomplete. Report observed,
inferred and unknown separately, including exact checks and remaining gates.
No fixed roster, issue quota, round count, grading service, scheduler or
evolution framework is installed by this workflow. Existing models, actual
parent permissions, capacity 23 and project-specific Git authority remain.
