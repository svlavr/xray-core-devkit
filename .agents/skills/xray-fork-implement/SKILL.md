# Accepted bounded implementation

Initialize with `xray-core-start`; confirm the accepted task/contract, missing
behavior, current reachable native owner, exact write set and dirty overlap.
The human supplies project scope and baseline under `docs/PROJECT_SCOPE.md`;
this toolkit defines no private modules, contracts or active stages. Apply
`xray-code-analysis` before shared/exported Go or responsibility moves.
Record hooks/state/locks/interfaces/dependencies, actual removal, validation and
stop conditions; no target/minimum/expected production-line ranges.

Compare native reuse, the smallest stock-local change and evidence-only scenarios.
Preserve native errors, cancellation/custody, batching/fast paths, packet
destinations, raw byte meanings, caller attribution and explicit partial/unknown.
Keep user traffic, internal control and measurements distinct where those owners
exist in the selected contract. No historical framework, speculative facade,
second engine or synthetic success. Preserve upstream ordinary native behavior.
Use one authoritative typed contract at a selected external boundary; application
policy, identity, rates/history/ranking and scheduling stay with their actual
owner unless the human's accepted scope explicitly places them here.

Main follows CODEX_PACK for early independent lanes, disjoint workers and stable
independent review. Workers are not alone and preserve others' edits. Native
children never change Git; external workers with owner-generated worker context
create local handoff commits only in assigned worktrees/local queue and return
exact SHA/tests/owned paths. They never publish or run the integrator checkpoint.

Follow `docs/WORKFLOW.md` accounting from startup through an authorized checkpoint:
capture before sizes, use the reviewed `.agents/metrics/modules.json` ownership
catalog and `.agents/metrics/source-size.json` snapshot, and include files/per-file
lengths plus fork added/deleted/net before/after. Separate runtime/tests/generated
code/test support/docs/tools, count shared integration once, explain growth and
declare baseline/catalog changes. The offline counter grants no deletion authority
or LOC quota. Missing project inputs remain explicit unresolved gates.

Validate affected behavior, race shared state and measure quantitative performance
claims. Preserve original tests and only explicitly supplied project exceptions.
Keep actual fixture FAILs and investigate their access pair/owner blobs under
`docs/WORKFLOW.md`; historical stock failures do not qualify changed fork code.
Do not repeat matching exact-source gates at handoff. Use Android validation only
for an accepted executable artifact or explicitly requested artifact validation.

Resolve integration blockers, record proved scope and remaining gates in the
human-selected task/plan, and use `xray-fork-checkpoint` within the explicit
repository policy. Automatic reviewed commit/push occurs only if the human
selected it; this distribution grants neither by default. Source changes may
trigger separately authorized exact-source CI; process-only work does not.
No implicit release, PR, tag, visibility/default change, binaries or retirement.
