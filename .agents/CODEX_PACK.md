# Xray Core Devkit agent pack

Read this compact entrypoint for every task. Read additional references only
when the accepted task needs them; availability is not a requirement to load
all policies, skills, role descriptions or tools into every session.

## Mandatory authority and access

The human owns task scope, source root, behavior contract, exact write set,
adopted upstream baseline and publication policy. This public toolkit does not
select or attach an existing source project and contains no product runtime,
private modules or stage authority. Main retains the human-selected model and
owns integration, validation and any authorized Git operation. Read the selected
root's `AGENTS.md` and applicable override before editing; preserve dirty overlap.

For toolkit maintenance, the root containing `devkit.py` is the task root. Use
`devkit.py verify`, `audit.py` and `workspace.py validate`; source setup/startup
requires an independently selected Xray source checkout. Installed source work
reads its accepted contract and ignored host context, then uses
`xray-core-start`. Startup reports facts and never starts a fetch, index, build,
implementation or publication. See `docs/PROJECT_SCOPE.md` for scope inputs.

Use one writer per checkout. Assign exact disjoint write sets or isolated
worktrees. Native children neither mutate Git nor spawn children. An external
writer commits only when explicitly authorized in its prepared isolated root;
main alone integrates and publishes. A consumer project's task does not authorize
source-fork edits. Missing scope/input/access is an explicit unresolved gate.

Read-only instructions and owned paths are mandatory task constraints. Role
`sandbox_mode` is intent, not a separately enforced boundary or a permission
grant. Actual parent sandbox/approvals determine access; no launcher/profile
expands them. Capability reductions are task-selected and must retain the tools
needed for the assigned outcome. Do not disable research for an entire role
catalog. Keep credentials, account files, raw logs/captures and host state out of
Git and public discovery services. Context7/grep.app/public research receive
public queries only; Repomix path scope is not disclosure clearance.

Internal analysis summaries, tasks/messages, tool queries, reports, handoffs,
queue comments, documentation and commit metadata use English. Only main's
direct human-chat replies use Russian. Preserve literal evidence/localization.
This is prompt policy, not evidence of unobservable reasoning.

## Select work and evidence

For substantial independent work, main records ready outputs, prerequisites,
owners, execution lanes and observed resources, then dispatches useful ready
lanes before detailed analysis. Explain coupled/deferred work; capacity 23 is
a bound, not a quota. Use `xray-orchestration` for lane selection and verified
external inputs. Never duplicate jobs or discard active jobs/uncollected results.

Use `session.py --list-roles` to select from the actual nineteen maintained role
descriptions. All eighteen skills remain available under `.agents/skills`.
Pass the selected `role` to the real execution route. Native custom-type
admission and CLI profile execution are different evidence; when native
admission is unavailable, use `session.py --role <name> --exec ...` or the bound
external route within existing authority. No repeated routine approval or new
chat is needed. Extra source-owned roles/skills remain owner-managed.

Models: `mu_explorer` is Luna high; ordinary role defaults are Sol 6.1 high.
Main automatically selects a matching bounded Terra high `task.preset` before
the first launch; read `docs/MODEL_ROUTING.md` and the exact preset scope in
`.agents/orchestration/model-presets.json`. Broader work retains Sol initially.
Unresolved Luna/Terra work returns scope/evidence to main without an automatic
model retry ladder;
`mu_deep_reviewer` is one Astra high adviser for a named technical discriminator
still unresolved after Sol. Missing input/access/validation is not escalation.
Preserve the parent model and explicitly bind routed model/effort/profile/skills
before model entry. Pools are execution targets, not specialist identities.
Only `mu_explorer` disables apps, plugins and memories for its narrow source
lookup. Shell and dedicated source MCP remain inherited within parent access.
The other eighteen profiles retain their configured research connectors; route
a broader external question to the appropriate maintained role.

Choose the least machinery that delivers the full justified behavior through
its real consumer. Use `xray-feature-delivery` for capability work and
`xray-solution-research` when the mechanism is uncertain. Preserve native errors,
resource custody, cancellation and honest partial/unknown outcomes. Explain
material requirement revisions; never relabel unfinished agreed behavior as
optional. Review stable non-trivial changes independently and repair findings.

Run host tests/builds through `resource_guard.py` with bounded time/output and
owned scratch. Reuse exact matching evidence; repeat after relevant changes or
new failures. Report only executed gates, including actual failures/skips.
Separate source/host, artifact/ABI, device, network, performance and release.
Tool configuration, invocation and confirmed results are distinct claims.

## Task-selected references

- Toolkit install/update/package and public-byte review: `docs/MAINTENANCE.md`.
- Source ownership, semantic/AST/reference or removal work: `xray-code-analysis`
  and `docs/ANALYSIS.md`; confirm actual `go_workspace` and profile first.
- Design uncertainty: `xray-design-exploration`; deciding executable experiments:
  `xray-decision-experiment`; workflow comparisons: `xray-agent-evaluation`.
- Changed wire/config/peer seams: `xray-protocol-compatibility`. Lifecycle,
  security, target/ABI or cost questions: selected `xray-runtime-qualification`
  references, without an automatic roster or platform matrix.
- Orchestration, frozen profiles, hooks, workers/resume and native routing:
  `docs/ORCHESTRATION.md` and `docs/AGENT_OPERATIONS.md` relevant sections.
- Source accounting, live/reused remote evidence, fixture races, validation and
  explicit checkpoint/export policy: `docs/WORKFLOW.md` and the task-selected
  `xray-fork-checkpoint` or `xray-public-ci` skill. No publication is authorized
  by this distribution; never export private working history.
- Host tooling/access, scratch lifetime, context diagnostics and detailed role
  selection: `docs/AGENT_OPERATIONS.md`. No startup indexing/build matrix.

Return DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT or BLOCKED with exact paths,
executed evidence and limits. External packets retain their assigned first-line
result envelope. A routed job, tool result or successful scratch experiment is
not completion of the consumer outcome or a grant of new authority.
