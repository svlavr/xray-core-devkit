# Xray Core Devkit contributor instructions

This is an independent public Xray-oriented Codex toolkit. Work only within the
human-approved task. Read `.agents/CODEX_PACK.md` for mandatory authority/access
and select its additional references by task. The distribution preserves all
nineteen maintained roles and eighteen skills; a task need not load them all.

The human selects the task root, behavior contract, exact write set, upstream
baseline and Git/publication policy. This repository does not select, connect,
configure, edit or publish any existing source project merely by being present.
Toolkit maintenance uses the root containing `devkit.py`; Go/runtime work needs
an explicitly selected installed Xray checkout. Follow `docs/PROJECT_SCOPE.md`
and the selected source's own instructions. Startup success grants no runtime
acceptance or publication authority.

Make focused changes, explain them before editing and summarize afterward.
Preserve dirty work; verify actual consumers before removal. Resolve ambiguous
behavior/authority before dependent work, continuing independent authorized work.
Main owns integration, validation and Git, retaining the human-selected model.
Use one writer per checkout and exact ownership. Native children neither mutate
Git nor spawn children; prepared external workers use only their assigned root,
queue and explicitly authorized local commit policy.

For substantial independent lanes, main records the ready frontier and delegates
useful ready work before detailed analysis. Use `xray-orchestration`; select real
role descriptions with `session.py --list-roles` and pass `role` to the actual
route. Luna high explores; Sol 6.1 high is the ordinary role default; matching
bounded tasks select Terra high through `task.preset` before their first launch.
Read `docs/MODEL_ROUTING.md`; no cheaper-model retry ladder is permitted. One Astra high
adviser resolves a named discriminator after Sol. Observed slots constrain the
configured capacity 23; capacity is not a quota. Preserve active jobs/results.

Actual parent sandbox/approvals determine tool access. Role sandbox metadata
states intent and grants no separate permissions. Read-only/owned-path constraints
remain mandatory. Apply only justified task-selected capability reductions and
retain required research/access. Native role admission, CLI execution, configured
tools, successful invocation and confirmed results are separate evidence.

Use `xray-feature-delivery` for capability work and `xray-solution-research` for
uncertain approaches. Deliver the full justified behavior through its real
consumer; explain material scope revisions. Select design/experiment, protocol,
runtime or workflow-evaluation skills only when the task implicates them. Review
stable non-trivial changes independently. See `docs/WORKFLOW.md` for detailed
validation/accounting/checkpoint policy and `docs/MAINTENANCE.md` for distribution
verification, clean package/install/update and dependency qualification.

Internal messages, analysis summaries, queries, reports, handoffs, documents and
commit metadata use English; only main's direct human-chat replies use Russian.
Keep host settings/secrets/raw evidence/caches/build output out of Git. Public
research services receive public queries only. Run host tests/builds through
`resource_guard.py`, bound time/output and preserve actual failures/skips.
Separate source/host, artifact/ABI, device, network, performance and release proof.

No automatic source publication is authorized. Git policy comes only from the
human's explicit task or saved settings for the exact repository/ref. Use exact
reviewed paths and bounded sequential Git. No force push, implicit PR/tag/release,
visibility/default change, binaries, archive or deletion. Filtered export requires
an owner-supplied `.agents/public-export.json` and explicit destination; never
publish a private working history directly.
